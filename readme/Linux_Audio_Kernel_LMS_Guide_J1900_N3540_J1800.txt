一、 Linux 音频专用内核核心优化思路
--------------------------------------------------------------------------------
编译适用于高品质音频播放（LMS / Squeezelite）的 Linux 内核，核心目标是降低音频中断（Xruns/Dropouts）、减少系统抖动（Jitter），并剥离无用硬件干扰：
1. 抢占模型（Preemption）：启用 CONFIG_PREEMPT=y（可抢占内核），显著降低音频线程调度延迟。
2. 定时器频率（HZ）：设置为 CONFIG_HZ_1000=y（1000Hz，1ms 滴答间隔）并开启高精度定时器 CONFIG_HIGH_RES_TIMERS=y。
3. 电源与频率锁定：默认锁定最高性能模式 CONFIG_CPU_FREQ_DEFAULT_GOV_PERFORMANCE=y，并通过启动参数限制 CPU 深度休眠（C-State），消除降频与唤醒导致的爆音。
4. 驱动内建（=y）：将 ALSA 核心、USB 音频驱动（CONFIG_SND_USB_AUDIO=y）、主板 USB 控制器及有线网卡驱动直接编入内核本体，减少模块加载延迟。
5. 无头精简（Headless）：关闭重型 3D 显卡驱动（CONFIG_DRM_I915）、无线蓝牙、防火墙（NETFILTER）及内核调试选项。

四、 内核编译、安装与 GRUB 引导参数配置
--------------------------------------------------------------------------------
1. 合并配置并编译（进入内核源码目录）：
   # J1900 / N3540（四核）：
   make defconfig
   ./scripts/kconfig/merge_config.sh .config j1900_n3540_lms_audio.config
   make olddefconfig
   make -j4
   sudo make modules_install
   sudo make install

   # J1800（双核）：
   make defconfig
   ./scripts/kconfig/merge_config.sh .config j1800_lms_audio.config
   make olddefconfig
   make -j2
   sudo make modules_install
   sudo make install

2. 更新 GRUB 引导参数（编辑 /etc/default/grub）：
   # J1900 / N3540（隔离第 4 核心 CPU 3）：
   GRUB_CMDLINE_LINUX_DEFAULT="quiet intel_idle.max_cstate=1 processor.max_cstate=1 isolcpus=3"

   # J1800（隔离第 2 核心 CPU 1）：
   GRUB_CMDLINE_LINUX_DEFAULT="quiet intel_idle.max_cstate=1 processor.max_cstate=1 isolcpus=1"

   更新引导并重启：
   sudo update-grub
   sudo reboot

五、 无 initramfs（直接引导内核）极速开机与网卡固件配置
--------------------------------------------------------------------------------
1. 检查网卡芯片与加载的固件文件名：
   lspci -nnk | grep -iA 3 "ethernet"
   sudo dmesg | grep -iE "r8169|igb|e1000e|firmware"
   * Intel 网卡（igb / e1000e）无需外部固件。
   * Realtek 网卡（r8169）若提示加载如 rtl_nic/rtl8168g-2.fw，需在内核配置中追加：
     CONFIG_FW_LOADER=y
     CONFIG_EXTRA_FIRMWARE="rtl_nic/rtl8168g-2.fw"
     CONFIG_EXTRA_FIRMWARE_DIR="/lib/firmware"
     CONFIG_BLK_DEV_SD=y
     CONFIG_SATA_AHCI=y
     CONFIG_EXT4_FS=y

2. 查询根分区 PARTUUID：
   findmnt -no SOURCE,PARTUUID /

3. 配置 /etc/default/grub 禁用 initrd：
   GRUB_DISABLE_INITRD=true
   GRUB_DISABLE_LINUX_UUID=true
   GRUB_CMDLINE_LINUX_DEFAULT="root=PARTUUID=<你的实际PARTUUID> rw quiet intel_idle.max_cstate=1 processor.max_cstate=1 isolcpus=3"
   （注：J1800 请将 isolcpus=3 改为 isolcpus=1）
   执行 sudo update-grub 生效。

六、 Squeezelite 核心隔离绑定（Systemd 配置）
--------------------------------------------------------------------------------
1. 执行 sudo systemctl edit squeezelite 并写入：
   [Service]
   # J1900/N3540 填 3，J1800 填 1
   CPUAffinity=3
   CPUSchedulingPolicy=fifo
   CPUSchedulingPriority=85
   LimitMEMLOCK=infinity

2. 编辑 /etc/default/squeezelite（Arch 为 /etc/squeezelite.conf）：
   SL_SOUNDCARD="hw:CARD=YourDAC,DEV=0"
   SB_EXTRA_ARGS="-a 80:4::1 -p 85 -C 5"

3. 重载并验证核心绑定（PSR 列应全部显示为 3 或 1）：
   sudo systemctl daemon-reload
   sudo systemctl restart squeezelite
   ps -mo pid,tid,psr,cls,rtprio,comm -C squeezelite

七、 多机协同架构（J1900/N3540 做主服务器 + J1800 做纯音频网桥）
--------------------------------------------------------------------------------
1. 角色分工：
   * J1900 / N3540（四核）：运行 Lyrion Music Server (LMS) 中心服务、挂载本地磁盘/NAS、兼任客厅转盘（CPU 0-2 运行 LMS，CPU 3 运行本地 Squeezelite）。
   * J1800（双核）：纯音频网桥（Pure Endpoint），禁用本地 LMS 服务（sudo systemctl disable --now logitechmediaserver lyrionmusicserver），仅运行 Squeezelite（CPU 0 处理网络/USB 中断，CPU 1 独占音频播放）。

2. J1800 网桥端 /etc/default/squeezelite 优化参数：
   SL_NAME="J1800-Bridge"
   SL_SOUNDCARD="hw:CARD=DAC,DEV=0"
   # -s 指定主服务器固定 IP；-b 4096:8192 增大网络流与输出缓冲
   SB_EXTRA_ARGS="-s 192.168.1.100 -b 4096:8192 -a 80:4::1 -p 85 -C 5"

3. LMS 中心服务器设置建议：
   * 文件类型（File Types）：FLAC / WAV / AIFF 保持原生（Native）直传；DSD 开启 Native DSD 或 DoP。
   * 多房间同步（Synchronize）：若多机同时发声有微弱回声，在“高级 -> 音频 -> 播放器启动延迟”中以 1ms 为步进微调延迟。
   * 网线建议：使用超五类或六类非屏蔽网线（UTP）连接千兆交换机，避免屏蔽层引发地线环路底噪。

八、 系统级一键调优与 USB DAC 硬件检测脚本（audio_tune.sh）
--------------------------------------------------------------------------------
保存为 audio_tune.sh，赋予权限 chmod +x audio_tune.sh 后使用 sudo ./audio_tune.sh 运行：

#!/usr/bin/env bash
set -e

if [[ $EUID -ne 0 ]]; then
   echo "错误：请使用 sudo 或 root 权限运行此脚本 (sudo bash audio_tune.sh)"
   exit 1
fi

echo "=========================================================="
echo "   Linux 专用音频系统一键调优与 USB DAC 硬件检测工具"
echo "=========================================================="

# 1. 写入网络与内存低延迟 sysctl 参数
echo "[1/4] 正在配置内核网络缓冲区与内存低延迟参数..."
cat << 'EOF' > /etc/sysctl.d/99-audio-tune.conf
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_rmem = 4096 87380 16777216
net.ipv4.tcp_wmem = 4096 65536 16777216
net.ipv4.tcp_slow_start_after_idle = 0
vm.swappiness = 0
EOF

sysctl --system > /dev/null
echo "      -> sysctl 参数已应用生效。"

# 2. 关闭 Swap 并注释 /etc/fstab 中的 swap 项
echo "[2/4] 正在禁用 Swap 交换分区..."
swapoff -a 2>/dev/null || true
if grep -qE '^[^#].*\sswap\s' /etc/fstab; then
    cp /etc/fstab /etc/fstab.bak.audio
    sed -i -E 's/^([^#].*\sswap\s.*)/#/' /etc/fstab
    echo "      -> 已禁用 Swap 并备份原 fstab 至 /etc/fstab.bak.audio。"
else
    echo "      -> 系统当前未启用持久化 Swap，无需修改。"
fi

# 3. 强制锁定所有 CPU 核心为 performance 模式
echo "[3/4] 正在锁定 CPU 频率调节器为 performance..."
if ls /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor 1> /dev/null 2>&1; then
    for gov in /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor; do
        echo "performance" > "$gov" 2>/dev/null || true
    done
    echo "      -> 当前 CPU 频率模式: $(cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor)"
else
    echo "      -> 未检测到 cpufreq 接口（可能已在 BIOS 锁定全速）。"
fi

# 4. 扫描声卡与 USB DAC 硬件能力
echo "[4/4] 正在检测系统声卡与 USB DAC 硬件参数..."
echo "----------------------------------------------------------"
if command -v aplay >/dev/null 2>&1; then
    aplay -l | grep -E "^card " || echo "未检测到播放设备！"
else
    echo "提示：未找到 aplay 命令，建议安装 alsa-utils"
fi
echo "----------------------------------------------------------"

for card_dir in /proc/asound/card*; do
    if [[ -f "$card_dir/stream0" ]]; then
        card_id=$(cat "$card_dir/id")
        echo "发现 USB 音频设备: [ $card_id ]"
        echo "建议 Squeezelite 设备参数: SL_SOUNDCARD="hw:CARD=${card_id},DEV=0""
        echo "硬件支持格式与采样率详情:"
        grep -E "Interface|Format:|Rates:|Channels:" "$card_dir/stream0" | sed 's/^/  /'
        echo "----------------------------------------------------------"
    fi
done

echo "调优与检测完成！建议重启一次系统以验证所有持久化设置。"

注:
SB_EXTRA_ARGS="-a 80:4::1 -p 85 -C 5" 
是 Squeezelite（开源 Squeezebox 音频播放器客户端）在 Linux 配置文件（通常为 /etc/default/squeezelite）中的附加启动参数。这组参数用于优化 ALSA 音频缓冲、提高音频线程优先级，并在空闲时自动释放声卡。

参数逐项解析

这行配置共包含三个核心开关选项：
• -a 80:4::1（ALSA 音频输出参数）。该选项的完整格式为 <b:p:f:m>，用于精细控制底层声卡的缓冲与行为：
	• 80（缓冲区大小）。将 ALSA 缓冲区设为 80 毫秒（默认通常为 40ms），有助于防止高码率音频播放时出现爆音或卡顿。
	• 4（周期数）。将缓冲区划分为 4 个周期（periods） 进行中断处理。
	• ::（采样格式留空）。两个冒号中间留空，表示不强制指定位深（如 16/24/32 bit），让 Squeezelite 自动匹配硬件支持的最佳格式。
	• 1（启用 mmap 模式）。开启直接内存访问（Memory-Mapped I/O），允许程序绕过部分内核复制直接向声卡写入数据，从而降低延迟与 CPU 占用。
• -p 85（实时线程优先级）。将音频输出线程的实时调度优先级设为 85（范围通常为 1–99，默认值为 45）。更高的优先级能确保系统在高负载下依然优先处理音频流，减少断音风险。
• -C 5（空闲自动关闭设备）。当播放器暂停或停止播放超过 5 秒后，自动释放并关闭声卡设备。这在多播放器共存的环境中非常实用，例如播放完音乐后允许 AirPlay（Shairport-sync）或 Spotify（Librespot）无缝接管同一块声卡。

适用场景与注意事项

• 典型适用硬件。这组参数常用于树莓派（Raspberry Pi）搭配外置 USB DAC 或 I2S 音频扩展板（HAT），适合追求低延迟、防爆音且多音频服务共存的场景。
• 硬件兼容性排查。部分较老或特殊的 USB DAC 声卡不支持 mmap 模式（即末尾的 1）。如果应用此配置后无法出声或报错，可将 -a 80:4::1 修改为 -a 80:4::0 进行测试。
• 生效方式。修改并保存 /etc/default/squeezelite 后，需运行 sudo systemctl restart squeezelite 重启服务使配置生效。

SB_EXTRA_ARGS="-D dop -p 99 -b 4096:6892"
这条配置指令是 Squeezelite（开源 Squeezebox 音频播放器）的环境变量设置，用于传递额外的命令行启动参数（常见于 Linux 系统的 /etc/default/squeezelite 或 piCorePlayer 等音乐播放系统中）。
它主要用于优化无损音频（特别是 DSD 格式）播放、降低爆音/卡顿，并提升系统音频处理的实时优先级。

参数逐项解析


参数	含义与作用
SB_EXTRA_ARGS="..."	环境变量名称。系统启动 Squeezelite 服务时，会自动读取双引号内的参数并附加到启动命令末尾。
-D dop	开启 DoP（DSD over PCM）支持。允许播放器将 DSD 高解析音频打包在 PCM 数据流中，发送给支持 DoP 的外接解码器（DAC）。（注：部分较新版本的 Squeezelite 中该参数简写为 -D）。
-p 99	设置实时线程优先级为 99。Linux 实时调度（RT priority）的范围通常为 1–99，设为最高值 99 可确保音频输出线程优先占用 CPU 资源，避免系统后台任务导致声音卡顿或爆音。
-b 4096:6892	设置内部缓冲区大小。格式为 <数据流缓冲区>:<输出缓冲区>（单位为 KB）。这里将流缓冲区设为 4096 KB（4 MB），输出缓冲区设为 6892 KB（约 6.7 MB），能有效应对网络波动并提高高码率音频播放的稳定性。


使用注意事项

• 需要 root 权限：-p 99 需要系统允许服务以高实时优先级运行（通常以 root 身份启动或配置了 rtprio 权限），否则启动时可能会报错或自动忽略该参数。
• 确认 DAC 兼容性：启用 -D dop 后，请确保你的 USB 解码器（DAC）硬件支持 DoP 协议。如果你的 DAC 支持原生 DSD（Native DSD）且 Linux 内核已适配，有时使用 -D :u32be 等原生参数效果更好。
• 生效方式：修改配置文件后，需要重启 Squeezelite 服务（如执行 sudo systemctl restart squeezelite）才能让新参数生效。

SB_EXTRA_ARGS="-p 99 -r 44100-48000 -b 2048:3445"

这是一行用于 Squeezelite（Lyrion / Logitech Media Server 的无界面音频播放器客户端）的额外启动参数配置，通常写在 /etc/default/squeezelite 或相关配置脚本中。
这段参数通过调整系统优先级、采样率限制和缓冲区大小，来优化音频播放的稳定性并防止爆音或卡顿。

参数逐项解析

• SB_EXTRA_ARGS="..."。这是 Squeezelite 启动脚本使用的环境变量，用于向主程序传递额外的命令行选项。
• -p 99。设置音频输出线程的实时优先级（Real-time Priority）。Linux 下的实时优先级范围为 1 到 99，设为 99 赋予了音频线程最高调度优先级，可避免其他后台任务抢占 CPU 导致声音断续或爆音。
• -r 44100-48000。限制声卡支持的最大与最小采样率范围为 44.1 kHz 到 48 kHz。如果播放高于 48 kHz（如 96 kHz 或 192 kHz）的母带音源，服务器（LMS）会自动将其重采样到该范围内再发送，适合老旧 DAC、部分蓝牙设备或特定板载声卡。
• -b 2048:3445。分别指定 流缓冲区（Stream Buffer） 和 输出缓冲区（Output Buffer） 的大小（单位为 KB）。前一个数字 2048（约 2 MB）用于缓存从网络接收的原始音频流，后一个数字 3445（约 3.4 MB）用于缓存解码后的 PCM 音频数据，有助于应对网络波动并降低硬件读写压力。

使用注意事项

• 权限要求。使用 -p 99 需要让运行 Squeezelite 的用户（如 squeezelite 或 root）拥有调整实时调度的系统权限（通常在 /etc/security/limits.conf 中配置 rtprio），否则服务启动时可能会报错或自动忽略该参数。
• 硬件匹配。如果你的外接 USB DAC 支持更高采样率（如 192 kHz 或 384 kHz），建议将 -r 参数调高（例如 -r 44100-192000）或直接删去该项，以免高解析度音频被强制降频损失音质。
